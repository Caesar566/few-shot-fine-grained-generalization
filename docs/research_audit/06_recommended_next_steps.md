# 下一步执行计划

本轮只审计并生成文档。下列修复、环境安装、训练和正式物种审核均未擅自执行。

## 1. 先建立正确性门槛

**优先C01、H04、H03。**

- 保留原始CUB与旧记录，对重复内容采用明确分组采样或版本化过滤。验收：同字节不同路径不能一张support、一张query；所有固定计划通过内容互斥检查。
- 泛化差距强制同一checkpoint哈希。验收：同配置但不同权重被拒绝；缺哈希不得默认为相同模型。
- 建立清单语义版本与原字节版本，处理CRLF/LF。验收：换行差异可审计兼容，真实内容变化拒绝；原历史记录保持不动。
- 澄清NABirds排除CUB训练物种还是全部CUB物种，固定物种层级单位。验收：公开书面协议，而非依赖脚本默认值猜测。

建议修复单独评审，不把实现修正与新成绩混在一个不可追踪的运行里。

## 2. 恢复可运行环境和低成本测试

采用项目Python 3.11和lock，不使用系统3.14冒充项目环境。恢复依赖涉及PyTorch较大安装，本轮没有执行。

先执行已有测试，测试临时目录应放在工程内（`project_output`限制产物必须位于工程中）；不要随意把pytest basetemp改到`/tmp`后把路径限制失败误判为模型故障。为审计使用新的专属临时目录，避免覆盖旧测试数据。

验收内容：

1. 导入与全部单元测试有原始退出码及日志。
2. 手算平方欧氏、余弦、马氏，核对协方差收缩与直接逆计算。
3. 手算DN4类别描述子池及top-k，输出尺寸与类顺序正确。
4. ProtoNet、DN4、Fusion、Matching/FCE前向及交叉熵有限，反传梯度有限。
5. 真实optimizer.step后adapter/温度发生预期更新；冻结骨干参数与BN状态保持预期。
6. eval前后state_dict一致，无意外参数或BN更新；单query预测不使用query真值。
7. 小型合成数据的train→best.pt→独立evaluate往返一致，保持不同shot标记。

这些通过才能说“框架可正常运行”；不能用34文件语法检查代替。

## 3. 恢复和核验旧产物

寻找报告引用的Windows工作目录或实验备份。每个关键运行至少恢复：best.pt、metrics.json、history.json、验证/测试计划、逐query记录、命令、配置、依赖版本、初始化权重来源与SHA256。

- 只读检查checkpoint架构、配置和原始哈希，按换行兼容方案核对清单。
- 按原计划重放一次推理，和逐query记录及摘要核对。
- 各初始化核验不同来源权重；源权重与训练后权重不能混用。
- 若无法恢复，旧摘要继续标“结果存在但证据不足”，按新实验名重训。不要把重新运行的结果写回旧JSON。

## 4. 准备NABirds正式物种审核

数据已经位于根目录`nabirds/`，无需重新下载或重复解压近10GB压缩包。使用显式`--data-root nabirds`，或另外评审规范目录方案。当前已验证48562个索引路径存在，不等于全部图像都可解码或物种已审核。

用现有工具生成**新的**待审核文件；审核者结合名称、同义名、层级、性别/年龄视觉子类确认物种祖先及排重。72个明显名称/祖先匹配候选仅提示风险，剩余没有候选也必须人工审查。不能用空模板或AI猜测填充`reviewer/evidence`。

验收：review与manifest可由原元信息重建；每物种满足shot+query；父子/视觉子类规则通过；审核人和证据真实；目标数据未被用于训练或调λ。

## 5. 冻结实验协议再开展正式比较

明确224分辨率、query数量、每seed任务数、训练预算、checkpoint选择shot、初始化来源、训练范围、λ/α/T选择方法和独立评估边界。旧CUB测试已查看，不能再称从未使用的盲测；若继续报告，应标探索性，或另行设计独立确认方案。

第一优先完成：Global、Local、Fusion在两域两shot的多seed对照及同checkpoint Δgen。随后按 [05](05_missing_experiments.md) 补表征、距离和组件消融。没有正提升也如实记录，不以达到5pp为由反复查看目标测试。

## 6. 最后再做解释和模型改进

确认主要结果后，补全query/原型/分支分数导出，盲法标注正确及错误样本的姿态、背景、遮挡、光照等因素。重复图像按独立图像处理，避免把同图多episode当独立证据。

只有在误差和消融支持具体假设后，再考虑分数标准化、分支校准、不同top-k或解冻范围。UMAP/t-SNE放在最后，只辅助解释。
